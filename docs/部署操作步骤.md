# 部署操作步骤 · HTTPS 上线（任务 8）

> 适用于境内服务器 `106.14.151.37`。把 `app.yyagent.top` 换成你的实际域名。
> 代码侧（nginx 配置示例、CORS 白名单、前端 API_BASE）已由 Claude Code 改好，本文是**人工照做清单**。

---

## 0. 前置：域名与备案

- 已有 `yyagent.top`，直接用子域 `app.yyagent.top` 即可。
- 在域名解析处加一条 A 记录：`app` → `106.14.151.37`。
- 境内服务器绑域名需 **ICP 备案**（约 1-2 周）；若主域已备案，子域通常可走"接入备案"较快。备案未下来前可先用已备案域名的子域过渡。
- 验证解析生效：
  ```bash
  ping app.yyagent.top   # 应返回 106.14.151.37
  ```

---

## 1. 安装 certbot 并申请免费证书

服务器上执行（以 Ubuntu + nginx 为例）：

```bash
# 安装 certbot
sudo apt update
sudo apt install -y certbot python3-certbot-nginx

# 申请证书（自动改 nginx 也可，这里用 webroot 手动模式更可控）
sudo mkdir -p /var/www/certbot
sudo certbot certonly --webroot -w /var/www/certbot -d app.yyagent.top
```

签发成功后证书位于：
- `/etc/letsencrypt/live/app.yyagent.top/fullchain.pem`
- `/etc/letsencrypt/live/app.yyagent.top/privkey.pem`

（这两个路径与 `backend/nginx.conf.example` 里的占位一致，无需改。）

---

## 2. 套用 nginx HTTPS 配置

```bash
# 把示例配置复制到 nginx
sudo cp /path/to/backend/nginx.conf.example /etc/nginx/conf.d/app.conf

# 编辑确认：把 server_name 和证书路径里的 app.yyagent.top 换成你的域名
sudo nano /etc/nginx/conf.d/app.conf

# 确认前端文件已放到 root 指向的目录（默认 /usr/share/nginx/html/index.html）
# 测试配置语法
sudo nginx -t

# 重载
sudo systemctl reload nginx
```

要点（已在示例里写好）：
- 80 端口整体 301 跳 443（保留 `/.well-known/acme-challenge/` 给续期校验）。
- 443 反代到 `http://localhost:3001`（Node 后端）。
- `client_max_body_size 80m`，与后端 `express.json({ limit:'80mb' })` 对齐。
- TLS1.2/1.3 + HSTS。

---

## 3. 后端 CORS 白名单（可选但建议）

代码已支持环境变量 `CORS_ORIGINS`（逗号分隔）。在后端 `.env` 里加：

```
CORS_ORIGINS=https://app.yyagent.top
```

- 不配置 → 兼容旧行为，全部放行（不影响现有部署）。
- 配置后 → 仅白名单 + localhost 调试端口可跨域。

改完重启后端进程（pm2 / systemd / 你现有的启动方式）。

---

## 4. 证书自动续期

certbot 默认装了定时任务，验证一下：

```bash
sudo certbot renew --dry-run
```

若使用 webroot 模式，确保 nginx 80 端口的 `/.well-known/acme-challenge/` 一直可访问（示例已配）。

---

## 5. 验收（你自己点）

1. 手机浏览器访问 `https://app.yyagent.top` → 地址栏出现锁标志 → 登录→生成→历史 全流程正常。
2. 访问 `http://106.14.151.37` 或 `http://app.yyagent.top` → 自动 301 跳转到 https。
3. 微信内打开链接 → 不再出现"不安全"提示。

任何一条不过：
- 跳转不生效 → 查 `/etc/nginx/conf.d/app.conf` 的 80 server 段与 `nginx -t`。
- 锁标志报错 → 查证书路径、`sudo certbot certificates` 看是否签发成功。
- 接口 403/CORS → 查 `.env` 的 `CORS_ORIGINS` 是否写对域名（带 https://，无尾斜杠）。
