# AI 写小说 · 设计规划

> 调研基础：[tianming-skill](https://github.com/zy-zmc/tianming-skill)（天命·长篇小说协同创作 Skill v2.0，995 行 Prompt 拆成 30+ 协议文件）。
> 本文把它的核心机制翻译成爆款工坊的 Web 产品形态，并最大化复用现有基建。

---

## 一、天命系统拆解（开源库学到什么）

### 1. 五件知识库（它的数据模型）

| 文件 | 性质 | 作用 |
|---|---|---|
| 世界基石.md | **动态**，系统维护 | 单一事实源：当前剧情状态、实体登记、伏笔台账。每章存档后更新 |
| 世界观规则.md | 静态，用户填 | 世界硬法则（力量体系、地理、规则代价） |
| 角色档案.md | 静态，用户填 | 角色烙印（性格底色、说话方式、关系向量） |
| 档案事件.md | 静态，用户填 | 既定事实时间线（同人/前传必填） |
| 文风样本.md | 静态，用户填 | 文气溯源——AI 模仿的范文 |

### 2. 指令式工作流（它的流程）

```
大纲（战略宏图+节奏宪章）→ 规划（全书蓝图）→ 目录（30章/批）
→ 草案（单章骨架，可选）→ 正文（单章3500-4000字）
→ 体检（一致性健康报告）→ 存档（结构化更新补丁→写回世界基石）
```

### 3. 最值得抄的四个机制

1. **存档补丁**：每章写完，系统产出「结构化更新补丁」（新增实体/状态变化/待决议事项），由用户确认后写回世界基石——**这是长篇不崩设定的关键**，和我们的"待确认池"是同一哲学。
2. **渐进式披露**：生成正文时只加载当前需要的协议和知识库切片，token 降 50-70%——和我们刚做的"阶段路由"同构。
3. **节奏量化**：冲突值五星制、峰值章节、三类缓冲章（代价/对话/线索）、伏笔三级（战略/战役/战术）——把"节奏"从玄学变成可校验的数。
4. **文风三件套**：文风样本（show）+ 写作戒律（tell）+ AI 指纹黑名单（禁）——和我们的 范例库+Skill规则+禁区 完全同构。

## 二、产品形态设计（Web 化翻译）

> 原则：天命是"文件+暗语指令"的极客系统；我们要做成"点按钮"的产品。
> 用户不需要知道「天命：正文」，只看到「生成本章」。

### 页面结构（复用原创工坊三栏工作区交互）

```
AI 写小说
├── 书架页（小说项目列表，类似原创文案首页）
│    └── 新建小说：类型(玄幻/都市/悬疑…) + 篇幅目标 + 一句话设定
├── 设定工坊（= 五件知识库的表单化）
│    ├── 世界观卡：力量体系/地理/硬规则（AI 可根据一句话设定生成初稿）
│    ├── 角色卡：可多张，烙印+口癖+关系（AI 辅助生成，用户改）
│    ├── 文风卡：贴 1-3 段你喜欢的范文（= 文风样本）
│    └── 世界基石：系统自动维护，用户只读+确认补丁
├── 大纲页：全书大纲 → 分卷 → 章节目录（批量生成，可改可重排）
└── 写作工作区（三栏，复用 do-ws 布局）
     ├── 左栏：卷/章节树（状态:未写/草案/已完成）+ 设定入口
     ├── 中栏：创作助手对话（调整剧情走向、改写、讨论）
     └── 右栏：本章正文文档（生成/编辑/保存，同活文档模式）
```

### 核心流程

1. **新建**：一句话设定 → AI 生成世界观卡/主角卡初稿 → 用户确认（10 分钟内开写）
2. **大纲**：AI 出全书大纲+分卷 → 用户改 → 生成本卷章节目录（每批 20-30 章）
3. **逐章写作**：点「生成本章」→（可选先出章节骨架确认）→ 出正文 3000-4000 字 → 对话式修改 → 定稿
4. **定稿即存档**：AI 产出本章「设定补丁」（新角色/状态变化/埋的伏笔）→ 进待确认 → 采纳后写入世界基石
5. **体检**（每 10 章提醒一次）：扫描伏笔未回收/角色状态矛盾/时间线冲突，出报告

### 每章生成时注入什么（上下文配方 = 渐进披露 Web 化）

```
固定：世界观卡摘要 + 相关角色卡（本章出场的）+ 文风卡范文
动态：世界基石的"当前状态"区 + 本卷大纲 + 本章目录条目
邻近：上一章结尾 800 字 + 前情提要（AI 维护的滚动摘要）
约束：小说写作戒律（Skill）+ AI 指纹黑名单（禁区，critic 硬校验）
```

## 三、技术方案（复用现有基建）

### 数据库（initDb 自建，沿用 cw_ 前缀风格）

```sql
nv_projects   (id, user_id, title, genre, brief, target_words,
               state JSON,        -- 世界基石：实体登记/伏笔台账/当前状态/滚动前情
               outline MEDIUMTEXT, status, meta JSON, created_at, updated_at)
nv_kb_cards   (id, project_id, kind ENUM(world/character/style/event),
               title, content MEDIUMTEXT, sort)
nv_chapters   (id, project_id, volume INT, seq INT, title,
               outline TEXT,      -- 本章目录条目（蓝图）
               content MEDIUMTEXT, word_count INT,
               status ENUM(todo/draft/final), updated_at)
nv_messages   (同 cw_original_messages 结构，挂 chapter_id)
```

### 接口（routes/novel.js 新文件）

| 接口 | 说明 |
|---|---|
| CRUD /api/novel/projects | 书架 |
| POST /projects/:id/kb/generate | 一句话设定 → AI 生成世界观/角色卡初稿 |
| CRUD /projects/:id/kb | 设定卡管理 |
| POST /projects/:id/outline | 全书大纲（同步，~30s） |
| POST /projects/:id/toc | 批量章节目录（同步） |
| POST /chapters/:id/generate | **异步任务**：正文 3500+ 字耗时 1-3 分钟，复用 tasks 表+轮询，避免 Zeabur 504（同 IndexTTS 模式） |
| POST /chapters/:id/chat | 对话修改（同原创工坊 chat 模式） |
| POST /chapters/:id/finalize | 定稿 → 触发设定补丁提取（异步）→ 待确认 |
| GET /projects/:id/health | 体检报告 |

### 直接复用的现有资产

| 现有资产 | 在小说区的角色 |
|---|---|
| do-ws 三栏工作区 + 对话/活文档交互 | 写作工作区（左栏换成章节树） |
| 待确认池（addPendingRule 模式） | 设定补丁确认 |
| 范例库机制 | 文风卡（show > tell） |
| 禁区 + critic 质检 | AI 指纹黑名单 + 每章硬校验 |
| 阶段路由思想 | 每章上下文配方（只注入相关切片） |
| taskRunner + tasks 表 | 正文异步生成 |
| callAI（bypassCap） | 长文生成 |

## 四、分期落地

| 期 | 内容 | 工作量估计 |
|---|---|---|
| **MVP** | 书架 + 设定卡（世界观/角色/文风，AI 辅助生成）+ 全书大纲 + 章节目录 + 逐章正文（异步）+ 对话修改 + 手动编辑/导出 txt | 4-5 天 |
| **P1** | 定稿设定补丁→世界基石（待确认模式）+ 前情滚动摘要 + 上一章衔接注入 | 2 天 |
| **P2** | 体检报告 + 伏笔台账 + 冲突值节奏标注 + AI 指纹黑名单预置词库 | 2 天 |
| **P3** | 多卷管理 + epub 导出 + 文风学习（定稿 diff 学习复用） | 按需 |

### MVP 刻意不做的

- 草案（章节骨架）环节——MVP 直接出正文，骨架并入"本章目录条目"
- 档案事件卡（同人向）——原创网文用不到，P3 看需求
- 冲突值量化——先靠大纲自然节奏，P2 再上

## 五、关键风险

1. **单章生成时长**：3500 字 + 长上下文 ≈ 1-3 分钟，必须走异步任务（教训：IndexTTS 504）。
2. **上下文膨胀**：30 章后世界基石会很大——靠"滚动前情摘要"（每章定稿后 AI 压缩一次）+ 只注入相关实体，MVP 就要做摘要，不能等。
3. **设定漂移**：用户跳过补丁确认会逐渐崩设定——补丁默认"建议采纳"一键全收，降低操作成本。
4. **成本**：一章 1 次生成 + 1 次补丁提取 + 可选 critic ≈ 3 次调用；100 章书 ≈ 300 次。需要在管理后台给小说区单独的模型配置（便宜模型写初稿、贵模型润色的双模型策略留接口）。
