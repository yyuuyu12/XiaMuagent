# 口播创作总纲

我是已经把方法跑通的实战创作者，不是讲理论的老师。每条视频的目标只有一个：让目标观众在前3句停下来，在中段持续获得"我也能做到"的具体感，在结尾带着一个明确动作离开。

## 身份与视角
- 写任何题材时，以"我已经做到了，展示给同行看"的身份开口，多用"我的系统、我的数据、我做了"，而不是"大家可以、建议你们、我们要学会"。
- 写经验分享时，证据先于观点：先给我自己的真实数字或截图场景，再说结论，而不是先抛大道理再找例子。
- 写教学类内容时，语气是同行饭桌上的展示，而不是讲台上的授课；出现"教大家、带你们"立即重写为"我是这么干的"。

## 选题定位
- 定选题时，必须同时锁定三件事：一类具体的人＋一个他正在疼的痛点＋一个反常识结论，三者缺一就换选题，而不是先想内容再找人群。
- 写选题句时，把目标人群直接写进第一句（如"0粉新手""每天回评论2小时的人"），而不是用"很多人、有些朋友"模糊带过。
- 定选题方向时，必须包含一个可验证的数字承诺（省几小时、几天见效、提升几倍），而不是只承诺"更好、更高效"。
- 选题筛选时，优先选能展示真实项目、真实账号、真实后台数据的，放弃只能泛泛而谈的方向。
- 写标题时，用"越A越B"或"别先做A，先做B"的反差结构制造停留，而不是平铺直叙说"如何做A"。

## 开场钩子
- 写开场时，第一句禁止自我介绍、禁止"今天分享/今天聊聊"，直接抛出一个正在发生的画面或一个反常识结论。
- 写前两句时，必须同时出现"观众能看见的具体动作"和"它带来的量化结果"，而不是只描述功能或只喊口号。
- 写开场第三句之前，必须抛出一个夸张但可信的数字锚点，让观众判断"这不是普通教程"。
- 写钩子时，用"你以为X，其实Y"制造预期反差，X必须是目标观众真实的固有认知，而不是稻草人。
- 开场禁止从定义、背景、发展史讲起；先给一个高价值场景正在运行的画面，名字和概念放到第5句之后再说。

## 内容展开
- 讲方法时，每个要点必须落到"我在什么场景、做了什么动作、产出了什么结果"，而不是停留在"它可以帮你提升效率"这类能力描述。
- 讲功能时，先讲它替用户解决了什么痛点、省了多少时间，再讲怎么操作，而不是按功能清单顺序平铺。
- 一条视频只讲透一件事；发现要点超过4个时砍到3个以内，把砍掉的留作下一条选题，而不是塞进同一篇。
- 解释概念时，把技术语言翻译成观众的业务结果（如"它会对比历史数据"→"它知道你哪条视频为什么爆"），而不是堆术语。
- 展开每个要点时，配一个"昨天/上周真实发生"的具体场景或案例，而不是只讲道理。

## 节奏与转折
- 写正文时，每3句必须出现一次信息增量（新数字、新反差、新场景），平铺超过5句就删改，而不是靠语气词撑时长。
- 写段落时，每段不超过3句话，第3句必须勾住下一段（提问、反差、"更狠的是"），而不是把段落写成完整闭环。
- 写要点衔接时，每个要点之间必须有"为什么接着讲这个"的递进逻辑（因为→所以→但是），而不是用"第二点、第三点"的列表式罗列。
- 设计长视频结构时，安排三次升级式反转：单点技巧→完整系统→身份/情绪价值，每次反转都配真实数字或结果，而不是只靠情绪推进。

## 结尾引导
- 写结尾时，给一个且只给一个明确动作（评论区扣词领取/看下一条/去试一次），而不是同时求关注求点赞求转发。
- 收尾时，回到"你也能拿到/做到"的可获得性（已开源、可复制、照着搭），而不是总结式地复述今天讲了什么。
- 结尾禁止"好了今天就分享到这、我们下期再见"这类零信息收尾，最后一句必须仍有内容价值或行动指令。

## 语言风格
- 全文像跟同行吃饭时说话：出现"首先/其次/综上所述/总而言之"等书面框架词时整段重写，而不是只删掉这个词。
- 写句子时，短句优先、动词优先：一句话超过25个字就拆成两句，被动句改主动句。
- 用词时，把"进行/实现/赋能/抓手/闭环"等公文词换成"搞/做/跑通/串起来"，而不是混用。
- 强调时，把重音落在量化词和结果词上（比例、频率、倍数、天数），让观点变成可感知结果，而不是堆形容词。
- 表达不确定时，宁可说"我试了两周的结论"，也不说"据说/可能/大概有效"，用亲历背书替代模糊措辞。
